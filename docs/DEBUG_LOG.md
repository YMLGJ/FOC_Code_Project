# 调试记录：12 个真实缺陷的完整根因

> 这份文档记录本项目从"波形全 0"到"无感闭环跑起来"的完整排障过程。
> 每个缺陷都包含**现象 → 错误判断 → 定位手段 → 根因 → 修复**。
> 留着它的目的：下次遇到同类现象，不用再从零猜一遍。

---

## 排障方法论（比任何单条结论都重要）

| 手段 | 解决的问题 |
|---|---|
| **加计数器**（`cmd_count` / `boot_count` / `main_loop_count`） | 区分"命令没收到" / "逻辑没执行" / "板子复位了" |
| **`RCC->CSR` 复位原因解码** | 区分上电复位 / 欠压(BOR) / NRST 脚 / 软件 / 看门狗 |
| **硬件异常捕获到 `.noinit` + 自动复位** | 把"静默停机"变成可读的 PC + CFSR |
| **文本调试通道 (`TXT 1`)** | 不再靠 16 个 float 通道猜 |
| **中断耗时 DWT 计数 + 超时计数** | 识别"CPU 被中断吃满、主循环饿死" |
| **反电势过零测速（模型无关）** | 判断转子真实转速，不被模型误差误导 |
| **栈水位（图样涂 + 扫描）** | 一次性排除栈溢出 |
| **SWD 直读 RAM** | USB 挂了也能看现场 |

## 缺陷 1：`DMAMUX1` 时钟未使能

| | |
|---|---|
| **现象** | `adc_raw` 恒为 0，三相电流全 0，但 `HAL_DMA_Init()` 和 `HAL_ADC_Start_DMA()` 都返回 `HAL_OK` |
| **根因** | STM32G4 的 DMA 请求要经过 DMAMUX。只开了 `DMA1_CLK_ENABLE()`，没开 `DMAMUX1_CLK_ENABLE()` |
| **修复** | `FOC_Current_DMA_Init()` 里补上 `__HAL_RCC_DMAMUX1_CLK_ENABLE()` |

**教训**：在 G4 上，DMA 初始化成功 ≠ DMA 能工作。要读 `adc_raw` 验证，不能只看返回值。

---

## 缺陷 2：ADC 自由运行与 PWM 异步

| | |
|---|---|
| **现象** | 电流值在 70~2089~4095 之间剧烈跳变 |
| **根因** | ADC 在 850 kHz 自由运行，与 20 kHz PWM 完全异步 → 严重混叠，采到开关瞬间的任意相位 |
| **修复** | 改为 `ExternalTrigConv = ADC_EXTERNALTRIG_T1_TRGO`，采样时间 47.5 cycles |

**教训**：电流采样必须与 PWM 同步，这是硬性要求。

---

## 缺陷 3：ADC1 顺序扫描两路

| | |
|---|---|
| **现象** | `Ia + Ib + Ic = +0.23 A ≠ 0`（星形连接应该严格为 0） |
| **根因** | ADC1 扫描 IU + IW 两路，IW 比 IU 晚采样 1.42 µs；2.4 A/µs 的 di/dt 下误差 3.4 A |
| **修复** | 只采 IU (ADC1) 和 IV (ADC2)，三相同时；`Ic = -(Ia + Ib)` |

**教训**：`Ia+Ib+Ic=0` 是免费的自检指标，随时该满足。

---

## 缺陷 4：PWM 通道与物理相交叉

| | |
|---|---|
| **现象** | 电流环怎么调都失控，`Id/Iq` 无意义 |
| **定位** | 万用表量线电压：`VD 0.5` + `DTC 0` 时 U-V=+0.04、V-W=-0.32、W-U=+0.29 → W 最高、U/V 等低；`VQ 0.3` 时 U-V=-0.18（负）→ 反相序 |
| **根因** | CH1→W、CH2→V、CH3→U（不是直连） |
| **修复** | `FOC_UpdatePWM()` 中交换 CCR1/CCR3 |

**教训**：**任何 dq 闭环之前，先用万用表确认 PWM 通道→物理相的映射。** 这一步省掉，后面全是玄学。

---

## 缺陷 5：电流传感器极性反

| | |
|---|---|
| **现象** | 映射修正后幅值正确（2:1:1）但符号全反 |
| **修复** | `FOC_CS_SIGN_IU/IV/IW = -1.0f` |

## 缺陷 6：预对齐用了 Iq

| | |
|---|---|
| **现象** | 转子停在偏离 90° 的位置，后续 I/f 打滑，Id 冲到 20 A |
| **根因** | Iq 产生力矩不产生定位；预对齐必须用 d 轴电流 |
| **修复** | `BSP_AlignMotor()` 只加 `Id_ref`，`Iq_ref = 0` |

---

## 缺陷 7：死区补偿缺失

| | |
|---|---|
| **现象** | 死区造成 0.226 V 压降，而 0.5 A 下只需要 0.035 V —— 大 6.5 倍 |
| **修复** | 加 `FOC_CompFactor()`，电流过零点线性过渡（避免小电流时自激抖动） |

---

## 缺陷 8：上电顺序导致零漂校准失败

| | |
|---|---|
| **现象** | `START` 被静默拒绝，电机不转 |
| **根因** | 先插 USB、后合母线。`FOC_Current_Init()` 后 10 ms 内就采完 400 点零漂，那时传感器还没电 → `off ≈ 137` → 超出合理范围 [1000, 3000] → `calibOk = 0` |
| **修复** | ① 合理性检查 + 重试 25 次；② 新增 `CAL` 命令，**不用断电就能重采** |

**教训**：上电顺序：**先合母线 → 等 2 秒 → 再插 USB**。反了就发 `CAL`。

---

## 缺陷 9：**40 kHz 中断超时 → 主循环饿死**（最隐蔽）

| | |
|---|---|
| **现象** | 一发 `START` 就"整块板子卡死"：USB 报"设备没有发挥作用"、波形冻结、命令全无响应、**但电机在正常转** |
| **错误判断** | 一开始怀疑栈溢出（栈其实有 120 KB 可用，根本不可能溢出）；又怀疑欠压复位 |
| **定位** | ① `g_isr_overrun = 1614396`、`g_foc_isr_cycles = 4953`（40 kHz 预算只有 4250）<br>② `g_main_loop_count` 60 秒只涨 525 |
| **根因** | 控制中断耗时 **4953 周期 > 4250 预算**，CPU 100% 困在中断里，`printf`/VOFA/命令解析全部停摆 |
| **修复** | PWM 从 40 kHz 降到 **20 kHz**（预算 8500 周期） |

**教训**：
- **"看起来死机、但电机还转"→ 先查中断耗时。**
- 主循环计数是最直接的"CPU 是否被饿死"指标。
- 中断里做的事越多（电流环 + 观测器 + 多次 `arm_sin_f32`），越要留足余量。

## 缺陷 10：`printf` 走 USART1，USB 上看不到

| | |
|---|---|
| **现象** | 排查全程没有任何文本反馈，只能靠 16 个 float 通道猜 |
| **修复** | 新增 `TXT <0\|1>`：模式 1 停二进制流、`printf` 改走 USB；`STATUS` 打印完整快照 |

另有 `%f` 格式化的隐患（newlib 里栈开销 400~600 B），全项目已改为整数打印。

## 缺陷 11：`g_last_cmd` 被 `DIAG` 自己覆盖

| | |
|---|---|
| **现象** | 诊断通道永远读出 `1`，无法判断上一条 START 是成功还是被拒 |
| **根因** | 命令解析入口 `g_last_cmd = 0`，`DIAG` 分支又置 `1` —— 查询命令把结果冲掉了 |
| **修复** | 改为 sticky，`DIAG` 不再修改它 |

**教训**：诊断代码本身也会有 bug，而且要优先怀疑它。

## 缺陷 12：观测器三个独立问题（依次暴露）

### 12.1 PLL 增益严重过大

| | |
|---|---|
| **现象** | `ω̂` 在 ±280 rad/s 乱飞（实际只需 ~29 rad/s） |
| **根因** | `Kp = 450`。对归一化误差 `eps_n ∈ [-1,1]`，Kp 直接决定 ω̂ 最大摆幅 —— 应按"能表达的最大转速"定，不能按理论带宽算 |
| **修复** | `450/98000` → `80/6400` |

### 12.2 锁定判据只看反电势幅值 → 18 A 失控

| | |
|---|---|
| **现象** | `Id` 冲到 **18.3 A**，`trip=1`（过流保护救了一命） |
| **根因** | `Eα = Vα - R·Iα` 在 18 A 时等于 `-R·I ≈ -1.1 V`，这个**直流分量**超过了 0.30 V 阈值 → 误判"已锁定" → 自动切到错误的观测角 → 电流失控 |
| **修复** | ① 新增**反电势过零法测真实电频率** `emfHz`（模型无关）；<br>② 锁定判据加入 `emfHz > 5 Hz`；<br>③ 自动切换再加"`emfHz` 与指令频率相差 <30%" 校验 |

**教训**：**幅值判据可以被直流偏置骗过去。必须要有"信号是否在真的周期变化"的判据**（过零点计数就是最便宜的一种）。

### 12.3 PLL 无法捕获频率差（决定性）

| | |
|---|---|
| **现象** | `locked=0`、`omega≈0`、`theta` 卡在 0，无论怎么调增益 |
| **关键数据** | `emfHz = 50000 mHz` 精确等于指令 50 Hz → **转子完全跟得上，不是失步** |
| **根因** | PLL 带宽 ≈12 Hz（ωn = √6400 = 80 rad/s），而 50 Hz 电频率是 **314 rad/s**。从 `ω̂ = 0` 起步**超出捕获范围**，相位误差长期饱和、积分正负抵消 |
| **修复** | **频率前馈**：`FOC_OBS_SetOmegaFF(foc->omega_elec)`，PLL 只在指令频率附近做微调 |

**结果**：`ω̂ = 305~323 rad/s`（理论 314.16），误差 <3%，`locked = 1`。

**教训**：**I/f → 无感交接必须让观测器从 I/f 的频率"接力"，不能从 0 起步。** 这是这类方案的标准做法，但很容易被忽略，且症状（`ω̂` 趴在 0）看起来很像"增益不对"。

## 附：环境层面的坑（非代码缺陷）

| 坑 | 现象 | 规避 |
|---|---|---|
| SWD 频率 800 kHz | `DEV_CONNECT_ERR`，连 ST-Link 序列号都读不出 | **必须 `freq=100`** |
| SWD 连接自动复位 MCU | 注入的命令/状态丢失 | 不能靠 SWD 交互调试 |
| 忘记重新 `objcopy` | 烧的是旧 `.bin`，调试结论全错 | 每次 build 后必跑 |
| ST-Link 3.3 V 与 buck 并联 | `RCC->CSR` 显示 `PINRSTF`，NRST 被拉低 | 二者只能接一个 |
| ST-Link 断开 3.3 V 后母线断电 | MCU 掉电，SWD/USB 全失 | 调试时母线必须开着 |
| VOFA 占用 COM4 | 脚本报"端口不存在/访问被拒绝" | 串口是独占资源，先断开 VOFA |
| 电机 USB 同时掉线 | 主机缓存设备失败状态，换口无效 | 断电重上电，或设备管理器卸载重装 |

## 一句话总结

> 这个项目里最难排查的从来不是算法，而是**观测手段缺失**：
> 没有文本通道、没有复位原因、没有异常记录、没有真实转速测量时，
> 每个现象都能编出三个看起来合理的错误解释。
> **先把"能看见"做好，再调参数。**
